# M0 baseline implementation plan

> Execution: implement inline with test-driven development; review the whole change before delivery. The user explicitly requested implementation without a planning approval stop.

**Goal:** Complete the independently testable M0 diagnostics and document the remaining L05C acceptance steps for Issue #1.

**Architecture:** Keep Python 3.10+ and the standard library. `diagnostics.py` owns bounded network checks; `cli.py` owns argument handling and private UTF-8 JSON exports. No Xiaomi login or bridge implementation in M0.

**Spec:** User request, Issues #1–#5, `docs/architecture.md`, and `docs/roadmap.md`.

## Constraints and decisions

- Reuse this fresh checkout on `feat/m0-baseline-diagnostics`; deliver a PR without merging or pushing main.
- `probe` accepts one numeric RFC1918 IPv4 host, retains the conservative .0/.255 rejection, validates all ports and timeout before connecting, and sends no application payload.
- Expose at most 32 unique ports and a finite timeout in (0, 10] seconds. Classify connection results without identifying application services or claiming device verification.
- `doctor` validates its HTTP(S) base URL, disables environment proxies and redirects, bounds the tags response to 1 MiB, and handles malformed responses. A reachable tags endpoint is not proof of inference.
- Reports carry schema/tool versions, UTC timestamp, and `device_tested: false`. Optional `--output` writes a new file only; raw reports remain private.
- Exit codes: 0 for completed diagnostics (including unavailable Ollama/no open ports), 2 for invalid input, 1 for report I/O failure.
- Windows is the primary development host; Mac mini M4 is a separate inference host. CI should cover Windows/macOS/Linux and Python 3.10 plus a newer interpreter.

## Review focus

- Invalid ports late in a list must not cause partial network activity.
- NaN/infinite timeouts must not reach socket/HTTP operations.
- Valid JSON with an invalid tags shape must not crash or look healthy.
- Redirects/proxies must not leak local diagnostics to another endpoint.
- Existing report files and errors containing secrets must not be printed or overwritten.
