## 发现及修复

| 问题 | 原因与影响 | 修改 |
|---|---|---|
| Ollama 异常 JSON 可能崩溃 | 默认 payload/models 均为预期字典/列表，顶层 list/null 等会触发 AttributeError/TypeError | 严格校验 models/name 结构、编码和 JSON；响应限 1 MiB；报告 `invalid_response` |
| URL/HTTP 行为不明确 | 任意 URL、系统代理及重定向可能检查到错误服务 | 仅 HTTP(S) 基础 URL，拒绝内嵌凭据/查询/片段，禁用代理和重定向；安全分类 HTTP/连接错误 |
| 端口校验可能在部分连接之后才失败 | 逐个连接前逐个校验；无超时边界和端口数量限制 | 全量预校验、最多 32 个不同端口、(0,10] 秒超时，去重保序 |
| 探测状态无法定位问题 | 拒绝、超时、本机权限/路由错误均被混为一类 | 区分连接状态、数值错误码和连接耗时；不识别服务或声称 SSH 可用 |
| 实验产物缺少可复现元信息 | stdout 只有基本结果，无法持久记录时间/版本 | schema/tool 版本、UTC 时间、明确硬件未验证标记，`--output` 保存新 UTF-8 文件 |
| CLI 缺少回归覆盖 | 原测试只覆盖少量模拟路径 | 增加本机真实 HTTP 合约测试和 CLI/文件 I/O/错误路径测试 |
| 文档缺少 Windows 优先流程 | Mac 被当作主要执行环境，原生体验没有逐次记录表 | Windows 非激活式 venv 命令、5 次计时及私有记录模板；区分公司 Mac 与家中网络 |
| 上游环境/凭据规则未核对 | M0 Python 版本不能代表 M1；`.env` 文件不等于实际载入 | 固定 XiaoAiAgent 检查提交、注明 Python 3.12+、额外适配包、进程环境变量及设备标识差异 |
| 日常发布指示直接推 main | 与独立分支/PR 约定冲突 | 修订发布流程，显式暂存检查过的文件，真机未验收时不自动关闭 Issue |
| CI 未覆盖承诺的平台/最低版本 | 仅 ubuntu/Python 3.11 | 配置 Windows/macOS/Linux × Python 3.10/3.12，并检查安装入口和编译 |

保留末尾 .0/.255 的保守地址限制并写明非 /24 局限；没有子网信息时不扩大扫描范围。CLI 版本升至 0.2.0，旧 `not_open_or_filtered` 使用者需迁移到新状态；详见实验 002 和架构中的报告合约。

## 独立审查及处理

独立只读审查复跑初版 31 项测试，发现有效 JSON 中的孤立 Unicode surrogate 模型名会被错误标为 `ok`，造成 UTF-8 stdout 编码异常或空导出文件。新增真实 HTTP 和 UTF-8 CLI/导出回归测试，先观察到失败，再校验模型名可编码为 UTF-8；最终完整套件 33/33 通过。无其他需修复项或暂缓的轻微项。

首次远端 CI 发现 Windows 英文环境下，33 项测试虽通过，但安装入口 `--help` 因默认 CP1252 无法编码中文而失败。已新增强制 CP1252 的真实子进程回归（帮助/参数错误输出），先复现失败，再在 CLI 解析参数前统一 stdout/stderr 为 UTF-8；完整套件变为 34/34。保留该记录，不将首次 CI 失败隐藏为“始终通过”。

审查边界的处理：

- 真机身份/固件/网络/声音及上游安装保留待验；没有证据就不验收，代价是 M0/M1 仍需要人类实验。
- HTTP 保留 socket 超时而非严格总期限；已说明 DNS/持续小量传输的例外，代价是异常服务可能延长命令耗时。
- 保留 .0/.255 保守拒绝；代价是某些非 /24 合法主机被拒绝，未来需明确掩码方案再扩展。
- Python API 按类型注解提供参数，CLI 负责文本解析；任意不符合注解的嵌入式调用不保证转换为统一错误，未来对外提供稳定库 API 时再扩展。
- 审查者没有重新抓取上游来源；本次实现者已通过 GitHub 连接读取固定提交的源文件并核对，仍不将源码事实当作运行成功。未来升级需重新核对并记录新提交。
