# 开发路线图（建议节奏，可调整）

| 里程碑 | 时间建议 | 交付物 | 验收条件 |
|---|---|---|---|
| M0 | 第 1 周 | 可运行 CLI、设备信息与只读网络基线、项目文档 | `doctor`/`probe` 可执行，能生成个人实验记录 |
| M1 | 第 2 周 | L05C + 上游 XiaoAiAgent 验证、Ollama 模型 | 实机完整走通「唤醒→ASR→Agent→TTS」1 次 |
| M2 | 第 3–4 周 | 模式切换、上下文记忆、超时/去重、时延记录 | 20 次测试记录成功率与分段耗时 |
| M3 | 第 5–6 周 | 英语练习 / 音乐控制 / 白名单工具 | 3 个常用技能能正常调用且拒绝危险命令 |
| M4 | 持续研究 | NuttX、固件、板级研究报告 | 每个结论都区分「来源已证实/假设/未测」 |

## 工作原则

1. 先调通现有开源链路，避免重复实现账号认证/协议。
2. M1 先只处理特定触发词，保留原生小爱回答能力。
3. M2 先观测再优化；记录版本、环境、网络、失败重试。
4. 只有证明软件路线无法满足目标，才评估拆机、UART 和固件研究。
